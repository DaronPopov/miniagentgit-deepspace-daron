# Hosted requalification gates

**NO-GO for hosted testing on the current evidence.** The local gate reduces
post-Worker resource use but leaves production ingress and billing unknown.
The installed parser still lacks a qualified hard resource boundary.
Live custom SQLite backup, route suspension and undeploy retention are open.

Before asking for separate deployment authorization:

1. Obtain confirmed protection on the canonical origin for approved
   accounts and real MCP clients, including direct-host attempts and
   provider-level admission before billable work. Establish Free exhaustion
   behavior, spending enforcement and the operation/resource metering limits.
2. Qualify hard parser resource enforcement and recovery for the deployed
   execution tier. Confirm a non-destructive suspend, backup and restore
   procedure that covers both custom SQLite classes and admission data.
3. Prepare verified production subject configuration in the supported
   secrets mechanism after approval. Verify issuer, audience, agent scope
   and minimal account authorization. Keep the existing app ID and no
   class deletions. Confirm the reviewed source and quota baseline.
4. With new deployment authorization, follow the bounded PASS 12A budget.
   Prove fresh provider OAuth, agent JWT issuance, actual coding-agent MCP
   discovery/invocation, two CI outcomes and dashboard reconnection,
   second-account isolation, replay and stale-HEAD behavior. Keep hosted
   output distinct from local fixtures. Abort on unknown spend or exposure.
